# Eventbus

> A small Elixir/OTP service that runs locally and accepts structured events from tools, scripts, editors, CLI commands, and local agents.

## Status

**In build**

Experimental project to do some work with Elixir. Goal to build out a small event bus for later desktop notifications and CLI. 

## Purpose

I wanted to do something to learn some Erlang/Elixir that I might actually use and that makes sense for the BEAM runtime. BEAM is the virutal machines used by Erland and Elixir and was built for systems that need long running processes, message passing, supervision, fault tolerance and isolation. They are useful properties for telecoms, chat systems, background workers and other local coordination tools.

## Summary

Eventbus accepts local development events such as:

```text
git.commit.created
repo.tests.failed
repo.tests.passed
model.loaded
model.unloaded
website.deploy.started
```

Subscribers can react to those events:

```text
notify me
write to log
append to SQLite
send desktop notification
trigger script
```

## Event model

Events are structured maps with a small required core:

```elixir
%{
  id: "evt_000001",
  topic: "repo.tests.failed",
  source: "repo",
  ts: "2026-07-01T09:30:00Z",
  payload: %{
    "command" => "cargo test",
    "exit_code" => 101
  }
}
```

Expected rules:

    * `id` is generated by Eventbus.
    * `topic` required.
    * `source` required.
    * `ts` generated by Eventbus.
    * `payload` optional.
    * `payload`, when present, must be a map.
    * Events should be append only.
    * Subscribers should receive event copies, not mutate shared state.

Topic names should use dotted segments:

```text
repo.tests.failed
model.loaded
website.deploy.finished
git.commit.created
```

Subscriber filters can support exact topics or prefix wildcards:

```text
repo.tests.failed
repo.*
git.push.*
model.*
website.deploy.*
```

## HTTP API Surface

Eventbus starts a local HTTP server on `127.0.0.1:4040` by default.

```bash
curl localhost:4040/health
```

Emit an event:

```bash
curl -X POST localhost:4040/events \
  -H "content-type: application/json" \
  -d '{"topic":"repo.tests.failed","source":"repo","payload":{"cmd":"cargo test"}}'
```

Read recent events, newest first:

```bash
curl localhost:4040/events/recent
```

## CLI surface

Build the local CLI escript:

```bash
mix escript.build
```

Check the running service:

```bash
./eventbus health
```

Emit an event:

```bash
./eventbus emit repo.tests.failed \
  --source repo \
  --json '{"cmd":"cargo test","exit_code":101}'
```

Read recent events:

```bash
./eventbus recent
```

The CLI defaults to `http://127.0.0.1:4040`. Override it with `EVENTBUS_URL`:

```bash
EVENTBUS_URL=http://127.0.0.1:4040 ./eventbus health
```

## File logging

File logging is disabled by default. Enable it in application config:

```elixir
config :eventbus, :file_logger,
  enabled: true,
  path: "eventbus_events.jsonl",
  patterns: ["*"]
```

When enabled, Eventbus appends one JSON object per line:

```json
{"id":"evt_000001","topic":"repo.tests.failed","source":"repo","ts":"2026-07-01T09:30:00Z","payload":{"cmd":"cargo test","exit_code":101}}
```

Supported patterns are exact topics, prefix wildcards ending in `.*`, and the all-events wildcard `*`.

## Desktop notifications

Desktop notifications are disabled by default. The first implementation targets Linux
`notify-send`, with the command kept configurable:

```elixir
config :eventbus, :desktop_notify,
  enabled: true,
  command: "notify-send",
  patterns: [
    "repo.tests.failed",
    "codex.run.finished",
    "website.deploy.finished"
  ]
```

Notifications use a short title such as `Eventbus: repo.tests.failed` and a body with
the event source and ID. Command failures are logged and do not affect event routing.
